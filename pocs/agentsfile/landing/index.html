The Dockerfile for agents

One Agentsfile declares the skills, agents, custom commands and MCP servers of a project, grouped into named profiles. Parse it from Python, Rust, Java, Go or TypeScript, and validate it with agentsfile-lint.

what goes in a profile

Four building blocks

A profile is a named set of blocks. A tool loads the profile it needs, such as dev or ci, and ignores the rest.

skill

Skills

A folder or URL with a skill definition, plus an optional description.

agent

Agents

The agent definition source, an optional model and the list of tools it may use.

command

Custom commands

Slash commands backed by a prompt file, declared once and reused across profiles.

mcp

MCP servers

stdio servers with command, args and env, or http and sse servers with url and headers.

${NAME}

No secrets in the file

Values like ${GITHUB_TOKEN} stay literal; the tool that applies the profile resolves them.

profile

Many profiles

Names are unique per file, and item names are unique per kind inside a profile.

syntax

Blocks like main.tf, strict like a compiler

Strings, lists of strings and maps of strings. Every SDK reports the first error with the same message and position.

version = "1"

profile "dev" {
  description = "Working on the Agentsfile spec and its SDKs"

  skill "agentsfile-lint" {
    source      = "./.agents/skills/agentsfile-lint"
    description = "Lints every Agentsfile in the repo"
  }

  agent "spec-guardian" {
    source = "./.agents/agents/spec-guardian.md"
    model  = "claude-opus-5-5"
    tools  = ["Read", "Grep", "Bash"]
  }

  command "conformance" {
    source      = "./.agents/commands/conformance.md"
    description = "Runs the conformance suite of every SDK"
  }

  mcp "filesystem" {
    transport = "stdio"
    command   = "npx"
    args      = ["-y", "@modelcontextprotocol/server-filesystem", "."]
  }
}
}

dev = file.profiles[0]
